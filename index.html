Bases de datos NoSQL

Referencia de Arquitectura de Datos y Web Semántica

MongoDB

Base de datos NoSQL orientada a documentos BSON (JSON binario). Destaca por su flexibilidad para almacenar esquemas dinámicos, su agilidad en el desarrollo y su facilidad para escalar horizontalmente mediante particionamiento (sharding).

Lectura

  • db.coleccion.find({ campo: "valor" }): Busca documentos.
  • Esquema:
    • db.coleccion.find({ BUSQUEDA }, { PROYECCION })
    • # Llaves 1 {}: Dónde se busca (Filtro). 1=está/cumple, 0=no está.
    • # Llaves 2 {}: Qué se muestra (Resultado). 1=ver campo, 0=ocultar campo.
    • Ejemplo: db.ejemplo.find({ age: 22 }, { nombre: 1, _id: 0 })
  • db.coleccion.find({ "direccion.ciudad": "Madrid" }): Dot notation para buscar en objetos anidados (obligatorio usar comillas).
  • .sort({ campo: 1 }): Ordena (1 ascendente, -1 descendente).
  • .limit(n) / .skip(n): Limita resultados o salta documentos.
  • db.coleccion.countDocuments({ filtro }): Conteo exacto de documentos que coinciden con el filtro.

Operadores de Búsqueda

  • Comparación: $eq (igual), $ne (distinto), $gt (mayor que), $gte (mayor o igual), $lt (menor que), $lte (menor o igual).
  • Lógicos: $and, $or, $not, $nor.
    Ej: db.ejemplo.find({ $or: [{ becado: true }, { edad: { $lt: 20 } }] })
  • Arrays: $in (valor dentro del array), $nin (valor no está).
    $size (busca arrays con una longitud exacta). Ej: { idiomas: { $size: 2 } }
    $elemMatch (encuentra documentos donde al menos un elemento del array cumple alguna condición).
    Ej: db.ejemplo.find({ compra: { $elemMatch: { producto: "huevos", cantidad: { $gt: 12 } } } })
  • Regex (Expresiones Regulares): Para buscar texto.
    Empieza por A: { nombre: { $regex: "^A" } }
    Termina en @hotmail.com: { email: { $regex: "@hotmail\\.com$" } }
  • Elementos: $exists: true (comprueba si el campo existe), $type (comprueba el tipo de dato).

Escritura y Borrado

  • db.coleccion.insertOne({ ... }): Inserta un documento.
  • db.coleccion.insertMany([ ... ]): Inserta varios documentos a la vez.
  • db.coleccion.deleteOne({ filtro }): Borra el primer documento que coincida.
  • db.coleccion.deleteMany({ filtro }): Borra todos los documentos que coincidan.

Actualización de Documentos

  • db.coleccion.updateOne({ filtro }, { $operadores }): Actualiza el primer documento que coincida.
  • db.coleccion.updateMany({ filtro }, { $operadores }): Actualiza todos los que coincidan.
    • $set: Modifica el valor de un campo o lo crea si no existe.
    • $inc: Incrementa un valor numérico. Ej: { $inc: { age: 1 } }
    • $rename: Cambia el nombre de un campo. Ej: { $rename: { "becado": "tieneBeca" } }
    • $unset: Elimina un campo completamente. Ej: { $unset: { becado: "" } }
    • $push: Añade un elemento al final de un array.
    • $pull: Elimina un elemento específico de un array.

Agregación (Aggregation Pipeline)

Procesamiento de datos en etapas secuenciales: db.coleccion.aggregate([ { etapa1 }, { etapa2 } ])

  • $match: Filtra documentos (misma sintaxis que `find()`).
    Ej: { $match: { total: { $gt: 100 } } }
  • $group: Agrupa documentos por un campo específico (`_id`) y aplica acumuladores.
    Ej: { $group: { _id: "$cliente", gastoTotal: { $sum: "$total" } } }
  • $unwind: Desglosa un array. Si un pedido tiene 3 productos, crea 3 documentos independientes para pasar a la siguiente etapa.
    Ej: { $unwind: "$productos" }
  • $sort: Ordena los resultados. Ej: { $sort: { gastoTotal: -1 } }
  • Operadores de fecha: $month, $year, etc. para agrupar.
    Ej: { $group: { _id: { $month: "$fecha" }, totalPedidos: { $sum: 1 } } }

Redis

Base de datos NoSQL en memoria de tipo Clave-Valor. Al almacenar los datos en la memoria RAM en lugar de en discos duros, ofrece latencias sub-milisegundo. Es la herramienta por excelencia para gestionar cachés, almacenar sesiones web, crear rankings en tiempo real y manejar colas de mensajería rápida.

Comandos Básicos (Strings)

  • SET clave "valor": Guarda un valor asignado a una clave.
  • GET clave: Recupera el valor de la clave.
  • DEL clave: Elimina la clave y su valor.
  • INCR / DECR clave: Incrementa o decrementa atómicamente un valor numérico (ideal para contadores).
  • EXISTS clave: Devuelve 1 si la clave existe, 0 si no.
  • EXPIRE clave 60: Define un tiempo de vida (TTL) de 60 segundos para la clave (se autodestruye).

Estructuras de Datos Avanzadas

  • Hashes (Objetos simples): Como objetos JSON de 1 nivel de profundidad.
    HSET usuario:100 nombre "Juan" age 28
    HGET usuario:100 nombre (Devuelve "Juan")
    HGETALL usuario:100 (Devuelve todos los campos y valores)
  • Lists (Listas/Arrays): Colecciones ordenadas según inserción (útil para colas/stacks).
    LPUSH cola_tareas "tarea1" (Añade por la izquierda/inicio)
    RPUSH cola_tareas "tarea2" (Añade por la derecha/final)
    RPOP cola_tareas (Saca y devuelve el último elemento)
  • Sets (Conjuntos): Colecciones desordenadas de strings únicos (sin duplicados).
    SADD etiquetas "nosql" "bd" "redis"
    SREM etiquetas "bd" (Elimina el elemento)
    SISMEMBER etiquetas "nosql" (Verifica si existe, O(1) de complejidad)
  • Sorted Sets (Conjuntos Ordenados): Conjuntos únicos pero con una "puntuación" (score) para ordenarlos (ideal para Leaderboards).
    ZADD ranking 1500 "Juan" (Añade a Juan con 1500 puntos)
    ZADD ranking 1800 "Ana"
    ZREVRANGE ranking 0 -1 WITHSCORES (Devuelve el ranking de mayor a menor)

Pub/Sub (Publicación/Suscripción)

  • Redis puede actuar como un broker de mensajería rápido (los mensajes no se guardan, es en tiempo real).
  • SUBSCRIBE canal_alertas: El cliente se queda escuchando ese canal.
  • PUBLISH canal_alertas "Error en el servidor": Envía el mensaje a todos los suscritos.

Persistencia en Redis

  • A pesar de ser "en memoria", Redis puede guardar los datos a disco de dos formas:
  • RDB (Redis Database): Toma "snapshots" (capturas) de la memoria cada X minutos. Consume pocos recursos pero puedes perder los últimos minutos si hay un fallo.
  • AOF (Append Only File): Guarda cada operación de escritura en un log. Es más seguro (no hay pérdida de datos) pero el archivo crece más y la recuperación es más lenta.

Cassandra (CQL)

Base de datos NoSQL distribuida y orientada a familias de columnas. Está construida para manejar cantidades masivas de datos a lo largo de múltiples servidores sin un único punto de fallo (arquitectura peer-to-peer). Es perfecta para cargas de trabajo con escrituras muy pesadas (IoT, registros, series temporales) donde la disponibilidad continua es prioritaria.

Estructura Lógica y Consistencia

  • Keyspace: Equivalente a la Base de Datos. Al crearlo se define la estrategia y el factor de replicación (ej: en cuántos nodos físicos se copia el dato).
  • Table o Column Family: Equivalente a las tablas relacionales.
  • Niveles de Consistencia: Cada consulta puede especificar cuántos nodos deben responder para considerarla exitosa. Ejemplos: ONE (rápido pero posible lectura sucia), QUORUM (mayoría, el más balanceado), ALL (seguro pero si cae un nodo, falla).
  • Tombstones: Al borrar un dato en Cassandra, no se elimina inmediatamente de disco, sino que se marca con una "lápida" (tombstone) que se propaga a los demás nodos. El borrado real ocurre más tarde (Compaction).

Comandos Principales CQL

  • Crear Keyspace:
    CREATE KEYSPACE mi_app WITH replication = {'class': 'SimpleStrategy', 'replication_factor' : 3};
  • Insertar Datos:
    INSERT INTO usuarios (id, nombre, email) VALUES (uuid(), 'Juan', 'juan@ejemplo.com');
  • Leer Datos:
    SELECT * FROM usuarios WHERE nombre = 'Juan' ALLOW FILTERING;
    Nota: ALLOW FILTERING es peligroso en producción porque escanea clústeres enteros si 'nombre' no es clave.
Modelado de Datos (La Clave Primaria es el Rey):

En Cassandra no se modela pensando en relaciones, sino en las consultas que vas a hacer. La PRIMARY KEY tiene dos partes:

PRIMARY KEY ((ciudad), edad, id_usuario)

1. Partition Key (ciudad): Decide en qué nodo físico del servidor se guardan los datos. Todos los usuarios de la misma ciudad van al mismo servidor.
2. Clustering Key edad, id_usuario: Decide cómo se ordenan los datos dentro de esa partición (nodo). En este caso, por edad y luego por id.

Regla de oro: Tus cláusulas WHERE deben usar siempre la Partition Key primero, o Cassandra se negará a ejecutar la consulta.

Neo4j (Cypher)

Motor principal de bases de datos NoSQL orientadas a Grafos de Propiedades. A diferencia de las BD relacionales, en Neo4j las relaciones son objetos de primera clase. Es indispensable para problemas donde el "cómo se conectan los datos" es más importante que el dato en sí (ej: prevención de fraude bancario, motores de recomendación, rutas de red).

Conceptos Clave del Grafo

  • Nodos (Nodes): Representan entidades (personas, productos, ciudades). Pueden tener cero, una o múltiples "Etiquetas" (Labels) para categorizarlos.
  • Relaciones (Relationships): Conectan dos nodos. Siempre tienen una dirección y un tipo. Una relación no puede existir sin un nodo de origen y destino.
  • Propiedades (Properties): Pares clave-valor (como JSON) que se pueden almacenar tanto en los Nodos como en las Relaciones. (Ej: Una relación "AMIGOS_DE" puede tener una propiedad "desde_año: 2015").

Lenguaje Cypher (Patrones)

Cypher usa arte ASCII para representar visualmente el grafo en las consultas:

  • (p:Persona): Los paréntesis representan un Nodo de la etiqueta Persona asignado a la variable 'p'.
  • -[:CONOCE_A]->: Las flechas y corchetes representan Relaciones y su dirección.

Operaciones Básicas (CRUD)

// 1. CREAR Nodos y Relaciones a la vez
CREATE (juan:Persona {nombre: 'Juan', edad: 30})
CREATE (madrid:Ciudad {nombre: 'Madrid', pais: 'España'})
CREATE (juan)-[:VIVE_EN {desde: 2018}]->(madrid)

// 2. LEER (Buscar patrones con MATCH)
// Encontrar todos los amigos de Juan que viven en Madrid
MATCH (p:Persona {nombre: 'Juan'})-[:CONOCE_A]->(amigo:Persona)-[:VIVE_EN]->(c:Ciudad {nombre: 'Madrid'})
RETURN amigo.nombre, amigo.edad

// 3. ACTUALIZAR (Modificar propiedades con SET)
MATCH (p:Persona {nombre: 'Juan'})
SET p.edad = 31, p.profesion = 'Ingeniero'
RETURN p

// 4. BORRAR (Nodos y sus relaciones)
MATCH (p:Persona {nombre: 'Juan'})
DETACH DELETE p // DETACH asegura que se borren primero sus relaciones, evitando nodos huérfanos

RDF & RDFS

El marco de trabajo (Resource Description Framework) principal de la Web Semántica del W3C. A diferencia de las BD transaccionales tradicionales, RDF está pensado para que la información de internet pueda ser leída y entendida por máquinas. RDFS (RDF Schema) amplía RDF proporcionando el vocabulario base para establecer jerarquías (clases y subclases).

Conceptos Fundamentales

  • Estructura del dato: Triples (Sujeto → Predicado → Objeto).
  • Identificación: Todo se identifica mediante URIs.

Vocabulario RDFS (Esquema básico)

  • rdfs:Class: Define una categoría o clase.
  • rdfs:subClassOf: Crea jerarquías de clases (ej: Mujer es subclase de Persona).
  • rdfs:Property: Define una relación o atributo.
  • rdfs:domain: Indica de qué clase es el sujeto de una propiedad.
  • rdfs:range: Indica de qué clase (o tipo de dato) es el objeto de una propiedad.
  • rdfs:label / rdfs:comment: Anotaciones para humanos.
  • Tipos de datos: Se usan los de XML Schema (ej: xsd:integer, xsd:string, xsd:date).

SPARQL

Es el lenguaje de consulta estándar (similar a SQL pero para grafos) diseñado para recuperar y manipular datos almacenados en formato RDF. Permite realizar consultas federadas, es decir, buscar información de forma simultánea a través de múltiples bases de conocimiento distribuidas por toda la web.

Consultas de lectura

  • FILTER: Filtra resultados por condiciones (ej: regex, >, <, !, &&, ||).
    • Empieza por: FILTER regex(?nombre, "^texto")
    • Termina en: FILTER regex(?nombre, "texto$")
    • Comodines (.*): El punto significa "cualquier carácter" y el asterisco "cero o más veces".
    • Nota: En SPARQL 1.1 es preferible usar las funciones nativas CONTAINS(), STRSTARTS() y STRENDS() ya que consumen menos recursos que regex (a menos que necesites patrones complejos con .*).
  • OPTIONAL: Busca datos que podrían no existir sin descartar el resto del resultado.
  • UNION: Combina los resultados de dos patrones distintos.
  • DISTINCT: Elimina resultados duplicados.
  • ORDER BY: Ordena por ASC (ascendente) o DESC (descendente).
  • LIMIT / OFFSET: Para paginación de resultados.
  • ASK: Devuelve un simple "sí" o "no" si el patrón existe.

Agrupación y Funciones

  • COUNT: Contar resultados (ej: COUNT(?person) AS ?total).
  • GROUP BY: Agrupar resultados por valores de una variable.
  • FECHA/HORA: NOW(), YEAR / MONTH / DAY.
  • MINUS: Excluir resultados (... MINUS { ... }).

Operaciones de escritura

  • Inserciones:
    • INSERT DATA { ... }: Inserta triples exactos.
      Ej: INSERT DATA { <http://ejemplo.org/Juan> <http://ejemplo.org/esAmigoDe> <http://ejemplo.org/Ana> }
    • INSERT { ... } WHERE { ... }: Inserta nuevos triples de forma basándose en los resultados de una consulta previa.
      Ej: INSERT { ?persona <ex:esAdulto> true } WHERE { ?persona <ex:edad> ?edad . FILTER(?edad >= 18) }
  • DELETE DATA { ... }: Borra triples exactos (sin usar variables).
  • DELETE { ... } WHERE { ... }: Borra datos dinámicamente usando variables que coincidan con el patrón del WHERE.
  • DELETE WHERE { ... }: Forma abreviada para borrar los triples que coincidan exactamente con el patrón de búsqueda.

Comandos cURL (Graph Store Protocol)

  • Recuperar un grafo (GET):
    curl -X GET http://[IP]:7200/repositories/[REPO]/rdf-graphs/service?graph=[URI_DEL_GRAFO]
  • Insertar un grafo (POST):
    curl -X POST --header 'Content-type: text/turtle' --data-binary '@ejemplo.ttl' http://[IP]:7200/repositories/[REPO]/rdf-graphs/service?graph=[URI_DEL_GRAFO]
  • Sobrescribir un grafo (PUT):
    curl -X PUT --header 'Content-type: text/turtle' --data-binary '@ejemplo2.ttl' http://[IP]:7200/repositories/[REPO]/rdf-graphs/service?graph=[URI_DEL_GRAFO]
  • Borrar un grafo (DELETE):
    curl -X DELETE http://[IP]:7200/repositories/[REPO]/rdf-graphs/service?graph=[URI_DEL_GRAFO]
  • Exportar Backup (TriG):
    curl -X GET -H "Accept: application/x-trig" http://[IP]:7200/repositories/[REPO]/statements > backup.trig
  • Ejecutar consulta SPARQL (POST):
    curl -X POST -H "Content-Type: application/sparql-query" -H "Accept: application/sparql-results+json" --data 'SELECT * WHERE { ?s ?p ?o } LIMIT 10' http://[IP]:7200/repositories/[REPO]
  • Limpiar todo el repositorio:
    curl -X DELETE http://[IP]:7200/repositories/[REPO]/statements
  • Realizar Backup (API REST):
    curl -X POST http://[IP]:7200/rest/recovery/backup # Crea una copia de seguridad en el servidor
  • Crear Repositorio:
    curl -X POST -H "Content-Type: multipart/form-data" -F "config=@config.ttl" http://[IP]:7200/rest/repositories

SHACL

El "Shapes Constraint Language" es un estándar de la Web Semántica utilizado para validar la estructura y el contenido de los grafos RDF. Se comporta de manera similar a JSON Schema en MongoDB, permitiendo asegurar la calidad de los datos forzando reglas de tipado, cardinalidades o restricciones de valores.

Shapes y Objetivos

  • sh:NodeShape: Restricciones sobre un nodo entero.
  • sh:PropertyShape: Restricciones sobre una propiedad específica.
  • sh:targetClass: Aplica la validación a todas las instancias de una clase.

Restricciones comunes

  • sh:minCount / sh:maxCount: Cardinalidad obligatoria.
  • sh:datatype: Obliga a un tipo de dato (ej: xsd:integer).
  • sh:pattern: El valor debe cumplir una expresión regular.
  • sh:closed true: No permite propiedades que no estén definidas en el shape.

Estructura SHACL

prefix : <http://ejemplo.com/ns#> .
prefix sh: <http://www.w3.org/ns/shacl#> .
prefix xsd: <http://www.w3.org/2001/XMLSchema#> .
prefix schema: <http://schema.org/> .

:UserShape a sh:NodeShape;       # decir que UserShape es de tipo sh:NodeShape (a = rdf:type)
   sh:targetClass :User ;        # Definir la clase a la que se aplica
   
   sh:property [                 # Cada restriccion a cada campo
    sh:path     schema:name ;    # A qué predicado se aplica la restriccion
    sh:minCount 1;               # Minimo cuantas relaciones tienes que haber de ese tipo
    sh:maxCount 1;               # Maximo cuantas relaciones tienes que haber de ese tipo
    sh:datatype xsd:string ;     # El tipo de dato al que tiene que apuntar esa relacion
  ] ;

  sh:property [
   sh:path schema:gender ;
   sh:minCount 1;
   sh:maxCount 1;
   sh:or (                       
    [ sh:in (schema:Male schema:Female) ] # Que el objeto sea literally una de esas opciones
    [ sh:datatype xsd:string ]
   )
  ] ;

  sh:property [
   sh:path     schema:knows ;
   sh:nodeKind sh:IRI ;          # A qué tipo de nodo puede apuntar la relación (IRI: que apunte a otro recurso)
   sh:class    :User ;           # A qué tipo de clase tiene que apuntar la relacion
  ] .

OWL

El "Web Ontology Language" es el lenguaje de modelado más potente y formal de la Web Semántica. Se fundamenta en Lógicas Descriptivas y permite construir ontologías avanzadas. A través de razonadores informáticos (reasoners), OWL permite a los sistemas "inferir" e "imaginar" nuevo conocimiento implícito que no estaba explícitamente guardado en la base de datos.

Relaciones entre Clases

  • owl:equivalentClass: Dos clases son idénticas.
  • owl:disjointWith: Un individuo NO puede pertenecer a ambas clases a la vez.

Object properties

  • Domain: Qué clase pueden ser sujetos de esa relación.
  • Range: Qué clase puede ser el objeto de esa relación.

Restricciones (Subclass Of)

  • VALUE: La relación debe apuntar a un individuo concreto (Ejemplo: vive_en value Madrid).
  • SOME (owl:someValuesFrom): Tiene que existir al menos una relación para esa clase a la clase objeto.
  • ONLY (owl:allValuesFrom): Solo puede haber relaciones de esa clase a la clase objeto (Ej: Rueda es parte de only coche).
  • MIN / MAX / EXACTLY: Tiene que haber mínimo, máximo o exactamente 'x' relaciones de esa clase a la clase objeto (puede haber otras relaciones con otras clases).

Características de Object Properties

  • TRANSITIVE: Si A → B y B → C entonces A → C.
  • SYMMETRIC: A ↔ B.
  • FUNCTIONAL: Un sujeto solo puede apuntar a un destino con esa relación (una persona solo puede tener una fecha de nacimiento).
  • INVERSE FUNCTIONAL: Un destino solo puede ser apuntado por un único sujeto (un ID de empleado solo puede ser apuntado por una única persona).
  • INVERSE OF (INVERSA): Definir qué relaciones son inversas (Ej: El coche vale más que la moto // La moto vale menos que el coche).
